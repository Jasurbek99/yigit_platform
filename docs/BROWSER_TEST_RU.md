# Тест в браузере — по шагам, по ролям

Простая инструкция. Для каждого шага написано: **под кем зайти**, **что нажать**, **что должно
получиться**. Ставь галочку, если совпало. Если не совпало — напиши, что было на самом деле.

- Адрес: **http://localhost:3000** или **http://10.10.11.25:8080**
- Логины и пароли: [TEST_ACCOUNTS.md](TEST_ACCOUNTS.md) — там же общий пароль для всех
  аккаунтов `t_*`. Этот файл в `.gitignore`; пароль здесь не пишем.
- Инструкция написана под **русский** интерфейс (как у тебя сейчас). Если язык
  переключат на туркменский, названия кнопок будут другие.

> ⚠️ **Число пунктов в меню НЕ равно числу прав.** В таблице части B указано количество
> страниц из прав (`page_permissions`), а в сайдбаре пунктов бывает больше: несколько ссылок
> ведут на один page_code (Отгрузки / Панель / Лист — все три это `export.shipments`), а
> **Карта автопарка** и **Управление автопарком** вообще не проверяют page_code — они открыты
> по отдельному списку ролей. Не считай это ошибкой.

> ⚠️ **Тест пишет настоящие данные.** Когда груз проходит все этапы, остаются записи в истории,
> в квотах, в задачах и в недельном плане. Если потом удалить груз — эти записи **не исчезнут**.
> Лучше тестировать на beta-сервере.
> Как убрать за собой: зайти под `admin` → открыть груз → удалить навсегда. Это работает
> **только пока груз в статусе Черновик**.

> ⚠️ **Между ролями выходи из системы полностью.** Иначе останется старая сессия и результат
> будет неправильный. Удобнее открывать каждую роль в отдельном приватном окне.

## Часть E — квота: срок действия и блокировка фирм (новое, 23.08.2026)

**Что изменилось.** Раньше фирма считалась «с квотой», пока в сезоне оставался хоть какой-то
остаток — даже если выдача просрочена месяц назад. Поэтому в Листе предлагалось ~20 фирм, хотя
реально квота была у одной. Теперь просроченная выдача не считается вообще.

**Сейчас квоты нет нигде:** в сезоне 2025-2026 все выдачи просрочены, в активном 2026-2027 их
ноль. Поэтому **все фирмы будут серые** — это не ошибка, это правда. Чтобы что-то проверить,
сначала нужно завести квоту.

> ⏱ После любого изменения квоты жди **до 60 секунд** или обнови страницу — балансы кэшируются.

### E1. Завести квоту (подготовка)

Зайти под `t_export_manager`.

1. Вверху справа переключатель сезона → **2026-2027**.
2. Открыть **Квоты** (`/export/quota`) → вкладка **Журнал выдач** → **Добавить выдачу**.
3. Заполнить: дата — **сегодня**, продукт — **томат**, срок — **этот месяц**,
   фирма **HG** — например `1 000 000` кг. Сохранить.
4. Ожидается: строка появилась в журнале, в **Разбивке по фирмам** у HG в колонке «Выдано»
   стоит 1 000 000.

### E2. Главная проверка — в Листе

1. Открыть **Лист** (`/export/sheet`), нажать на ячейку **Экспортные фирмы** любой машины.
2. Ожидается: **HG выбирается**, все остальные фирмы серые, с пометкой **⚠ нет квоты**, и внизу
   есть ссылка **«Открыть страницу квот →»**.
3. Выбрать HG → **Готово**. Ожидается: сохранилось без ошибки.
4. Вернуться в **Квоты** → у HG в колонке «Использовано» появился вес этой машины.

### E3. Проверка самого срока действия (не дожидаясь конца месяца)

1. В журнале выдач добавить **вторую** выдачу: дата **01.06.2026**, срок — **этот месяц**,
   фирма **MA** — `500 000` кг. (Дата старая → срок истёк 30.06.2026.)
2. Открыть Лист → ячейку фирм. Ожидается: **MA осталась серой** — просроченная квота не даёт
   права выбрать фирму. Это и есть проверяемое исправление; до него MA стала бы доступной.
3. Открыть **Квоты** → **Разбивка по фирмам**: у MA эти 500 000 должны быть в колонке
   **«Просрочено неиспользовано»**.
4. Удалить эту тестовую выдачу.

### E4. Уже назначенные фирмы не должны ломаться

1. Найти машину, где фирма **уже стоит** в сплите (любая, даже без квоты).
2. Открыть ячейку фирм, изменить вес, сохранить.
3. Ожидается: **сохраняется**. Блокировка касается только **добавления новой** фирмы без квоты.

### E5. Проверка через API (по желанию)

Открыть в браузере (под тем же логином):
`/api/v1/export/quota-firm-balances/?product_type=tomato`
Ожидается: `remaining_kg` больше нуля **только у HG**.

### E6. Квота, попавшая не в тот сезон (команда для админа)

Так бывает: квоту на новый сезон заводят раньше, чем админ откроет сезон, — и она падает в
старый. Тогда в активном сезоне квоты нет и **блокируются все фирмы**.

1. Специально повторить: переключить сезон на **2025-2026**, завести выдачу с **сегодняшней**
   датой на любую фирму.
2. В Листе (на активном сезоне) эта фирма останется серой — квота ушла в чужой сезон.
3. Админ на сервере выполняет:
   `python manage.py fix_quota_issuance_seasons --dry-run` — должно вывести эту выдачу и
   куда она переедет; затем без `--dry-run`.
4. Ожидается: в Листе фирма становится доступной (в течение минуты).

## Часть F — Контракты, Документы, Продажи (новое, 24.08.2026)

**Как это устроено, простыми словами.**

Три экрана в меню, и груз проходит через них по очереди слева направо:

```
  ЛИСТ                      ДОКУМЕНТЫ                  КОНТРАКТЫ / ПРОДАЖИ
(создали груз)     →   (привязали к договору,   →   (сам договор, список
                        распечатали бумаги)          продаж, итоговые суммы)
```

1. **Лист** (`/export/sheet`) — здесь груз (одна машина) уже существует, у него заполнено
   поле **«Покупатель»** и ячейка **«Экспортные фирмы»**: в этой ячейке указано, какая фирма (или
   2-3 фирмы) продают этот груз и сколько кг у каждой. Это обычная работа с Листом, ничего
   нового здесь делать не нужно.

2. **Документы** (`/documents`) — список грузов, каждый разворачивается кликом. Внутри —
   по одной строке на каждую фирму из ячейки «Экспортные фирмы». Пока у строки фирмы нет
   договора, рядом с ней кнопка **«Привязать контракт»**. Нажимаешь — открывается маленькое
   окошко, где либо выбираешь уже существующий договор этой фирмы с этим покупателем из списка,
   либо жмёшь **«Создать разовый»**, если такого договора ещё нет — тогда программа сама создаёт
   новый номер договора. После этого рядом с фирмой появляются кнопки печати: **CMR** (одна на
   весь груз) и **«Инвойс»** (своя у каждой привязанной фирмы), а также **«Скачать пакет»** —
   все бумаги груза одним архивом.

   *Почему у грузa может быть 2-3 договора, а не один?* Одну машину иногда специально делят
   между двумя фирмами-продавцами, чтобы сумма счёта каждой фирмы была меньше $10 000
   (правило банка: счёт от $10 000 и выше проводится только через банк, меньше — можно
   наличными). Тогда у каждой фирмы — свой номер договора, своя строка «Привязать контракт»,
   свой инвойс и своя CMR.

3. **Контракты** и **Продажи** (`/contracts`, `/sales`) — здесь видно уже готовые договоры и
   список всех привязанных продаж. Открываешь договор — сверху написано, сколько машин/кг/$ по
   нему уже отгружено и сколько осталось по плану. Эти цифры программа считает сама, как только
   на странице Документы что-то привязали, — руками их никто не вписывает.

**Итог: чтобы у груза появились документы и договор, всегда один и тот же путь —**
заполнить фирму на Листе → зайти на Документы → нажать «Привязать контракт» у каждой фирмы →
распечатать CMR/инвойс/пакет. Проверить результат можно на страницах Контракты и Продажи.

### F1. Подготовка — груз с покупателем и фирмой

Под `t_export_manager` (у него по умолчанию есть право и на контракты, и на продажи).

1. [ ] Открыть Лист, взять груз со статусом после Черновика, у которого уже заполнены
   **страна + покупатель** (можно один из грузов Части A).
2. [ ] В ячейке **Экспортные фирмы** выбрать хотя бы одну фирму, указать вес. Сохранить.
3. [ ] Запиши код груза (например `02FB005/26`) — понадобится на следующих шагах.

### F2. Привязка контракта — страница Документы

4. [ ] Открыть **Документы** (`/documents`). Найти строку с этим кодом груза (можно
   отфильтровать по дате сверху) и раскрыть её.
5. [ ] Если сверху жёлтое предупреждение «Сначала заполните в Листе: …» — там перечислены
   `покупатель`, `страна`, `водитель` или `номер машины`; вернуться в Лист и дозаполнить
   недостающее, потом обновить страницу Документов.
6. [ ] У фирмы без контракта — кнопка **«Привязать контракт»**. Нажать.
7. [ ] На панели: если для пары «фирма + покупатель» есть рамочный контракт — он уже выбран в
   списке, подтвердить. Если списка нет — нажать **«Создать разовый»** (эта кнопка есть всегда).
8. [ ] Ожидается: всплывающее сообщение «Контракт … привязан» + подсказка про банк ($ ≥10 000)
   или наличные (< $10 000).
9. [ ] Кнопка **«Привязать контракт»** у этой фирмы исчезла, вместо неё — кнопка инвойса.
   Контракт привязан.

### F3. Документы — CMR, инвойс, пакет

10. [ ] Если статус упаковки — «Нет упаковки» — кнопка **«Заполнить упаковку»** активна
    (красная, пунктирная). Заполнить брутто/нетто/ящики/поддоны, сохранить — кнопка исчезает.
11. [ ] Нажать **CMR** — файл должен скачаться и открыться.
12. [ ] У привязанной фирмы нажать кнопку **«Инвойс»** — должен скачаться инвойс именно на эту
    фирму, не на весь груз.
13. [ ] Кнопка **«Скачать пакет»** (ZIP) — активна, только когда груз полностью готов
    (`is_ready`: заполнена упаковка + нет предупреждения из шага 5). Нажать — должен скачаться
    архив с документами.

### F4. Проверка — контракт и продажа обновились

14. [ ] Открыть **Список контрактов** (`/contracts`), открыть контракт, который привязали
    в F2 (можно по ссылке на панели).
15. [ ] В шапке: **Экспортировано машин/кг/$** увеличилось на этот груз, **Остаток**
    уменьшился ровно настолько же. Значения посчитались сами — никто их не вводил.
16. [ ] На вкладке **«Продажи по контракту»** — новая строка; код груза в ней кликабелен и
    ведёт на `/export/shipments/{id}`.
17. [ ] Открыть **Продажи** (`/sales`) — та же строка видна в общем списке (фильтр по статусу
    сверху, поиск по коду груза/контракту).

### F5. Запреты — кто НЕ должен привязывать контракт или создавать продажи

По коду (`ContractViewSet`/`ContractSaleViewSet`) писать в контракты и продажи по умолчанию
могут только `admin`, `director`, `export_manager`. Видимость пункта меню и право на запись —
**разные вещи**: у `t_document_team` пункты «Договоры»/«Документы» в меню есть (Часть B), но
права на создание может не быть.

18. [ ] Зайти под `t_document_team`. Открыть **Документы**, попробовать **«Привязать контракт»**
    у непривязанной фирмы. По документации кода — должен быть запрет. Если получилось —
    это несостыковка кода и документации, запиши как находку (по образцу F12/F13 выше).
19. [ ] Зайти под `t_boss`. Открыть **Список контрактов** — список виден (view-only), кнопок
    создания/правки быть не должно.
20. [ ] Зайти под `t_weight_master` или `sales_rep` — пунктов «Договоры»/«Документы»/«Продажи»
    в меню быть не должно вовсе (сверься со списком в Части B).
