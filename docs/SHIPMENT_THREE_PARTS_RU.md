# Шипмент из трёх частей — как я понял процесс

**Дата:** 2026-09-24 · **Статус:** обсуждение, ничего не решено. Это рабочая заметка для сверки,
не спецификация. **(?)** = моё допущение — поправь.

## 1. Процесс (из твоего сообщения)

1. **Пт** — менеджер теплицы: недельный план сбора по блокам. *(есть)*
2. **Сб** — Gadam (export_manager): сколько машин в какие страны по дням. *(есть: `WeeklyTruckAllocation` + `TruckDestinationSplit`)*
3. **Транспорт** (Malik, Haltaç) по этому распределению планирует машину + водителя + рейс и отдаёт частями — на всю неделю или по дням → **транспортная часть**. *(нет в системе)*
4. **Каждый день** Soltanmyrat (loading_dept_head): сколько кг и с каких блоков грузить → **часть упаковки**. *(есть: supply-черновик / Gaplama «Tır Aç»)*
5. **Каждый день** Gadam: страна, импортёр, план кг, тип gapy / regular → **экспортная часть**. *(есть: destination-черновик)*
6. **Док. команда:** экспортная фирма (по квоте) → брутто/нетто → **старт подготовки документов**.
7. **Regular:** Gadam выбирает машину из транспортной части и присоединяет.
   **Gapy:** транспортной части нет, машину и водителя вводит док. команда или Gadam.
8. Документы готовы, таможня пройдена → дальше (погрузка) нельзя, пока не присоединена упаковка. Присоединить можно и раньше.
9. Упаковку (экспорт-код, блоки, кг, тип **(?)**) можно поменять или взять с другого шипмента — только уведомление + лог, ничего не перезапускается. Можно даже когда машина уже в теплице.
10. Приезд в теплицу → погрузка → конец погрузки → выезд. Gapy на выезде закрывается, regular едет дальше.

Transport bölegi**, ru **план поставки / план назначения / план транспорта**.

|---|---|---|---|---|
| Транспорт (план транспорта, Transport bölegi) | transport (Malik, Haltaç) | с субботы, частями | голова + прицеп, водитель(и), рейс | записи нет — транспорт пишет прямо в колонки `Shipment` (`truck_plate`, `driver_name`, `truck_head_id`…); `trip_id` — просто число |

## 4. Что это ломает в текущем коде

1. **Join = склейка, а не ссылка.** `_execute_join` (`backend/apps/export/views.py:2478`) переносит
   блоки в экспортную строку и **удаляет** строку упаковки; работает только когда обе — `draft`.
   R2 и R5 требуют, чтобы части жили после присоединения (упаковку переставляют, смена машины
   «доходит» до шипмента) → нужна ссылка. Спек Tırlar (§7 «Ayır»,
   `2026-09-16-tirlar-sera-design.md`) упёрся в то же: у Join нет обратной операции.
2. **Барьер не на том шаге.** `transition_to` не выпускает шипмент из `draft` без блоков
   (`backend/apps/export/services/shipment.py:256`). По R4 документы идут первыми → барьер
   переезжает на `gumruk_chykysh → yuklenme`, а присоединение должно работать и после `draft`.
3. **Транспортной части нет как записи.** DOMAIN.md называет внешний Trip Management источником
   рейсов. Правило зависимостей: `export` не может ссылаться на `transport` → ссылка должна жить
   на стороне `transport` (`transport → export` разрешено).
4. **«Документы заново» = уже решённый откат C** (`2026-09-24-task-lifecycle-roadmap.md`: статус
   реально идёт назад, причина → шаг, «замена машины» — там же пример). Здесь причина системная
   и срабатывает сама. Но C по утверждённому порядку последний: B → редактор правил → A → C.
5. **Риск каскада.** Любой сброс `documents_status` или задач может запустить
   `auto_advance_if_ready` и сдвинуть машину побочным эффектом. Каждый подпроект обязан сказать,
   как этого избегает.

## 5. Кто читает эти поля прямо из `Shipment` (цена любого переноса)

- Шаблоны CMR / TIR carnet / инвойса — плоские поля транспорта (номер, водитель, паспорта).
- Gaplama «Tıra giden» и факт недельного плана (`actual_rollup`) — суммы `ShipmentBlockSource` по шипменту.
- Swap (`swap_config.py`) — белый список полей.
- Правила задач (`seed_task_rules.py`) — `target_fields`: `driver_name`, `truck_plate`, `block_sources`…
- Строки Sheet (`sheet_rows.py`), сериализаторы, типы на фронте.

## 6. Разбивка на подпроекты

- **(a)** Транспортная часть — своя запись из субботнего распределения; Gadam присоединяет её к экспортной.
- **(b)** Упаковка — ссылка вместо склейки, позднее присоединение (R4), замена с уведомлением (R5).
- **(c)** Документы заново при смене машины (R1–R3) = откат C.
