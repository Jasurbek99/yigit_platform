# Бланк фирмы и номер письма в СТ-1 / Фито / ARZA — design

**Date:** 2026-10-05
**Status:** approved in chat 2026-10-05, spec awaiting review, not built
**Builds on:** автонумерация инвойсов
(`docs/superpowers/specs/2026-10-03-invoice-auto-numbering-design.md`), её паттерн floor-таблицы
и выдачи. От её незавершённой задачи 3 не зависит, см. §6.
**Plan:** `docs/superpowers/plans/2026-10-05-firm-letterhead-letter-numbers.md`

## Problem

Три письма в органы — запрос СТ-1 (`ct1_ru`), запрос фитосертификата (`fito_ru`) и таможенная
ARZA (`customs_tk`) — сейчас печатаются без шапки фирмы и без номера. На бумаге каждая фирма
отправляет их на своём фирменном бланке (пример: `data/Yigit_header.docx`) с исходящим номером.

## Decisions taken (owner, 2026-10-05)

| Вопрос | Ответ |
|---|---|
| Где хранится бланк | У экспортной фирмы, загружается в её карточке. Новая загрузка заменяет старую, истории версий нет |
| Строка ««__» ___ 20 ý.» | Дата **не** заполняется, остаётся для ручного заполнения |
| Номер письма | Генерируется и печатается в «№ ___» бланка |
| Область счётчика | Экспортная фирма × вид письма (СТ-1 / Фито / ARZA) × календарный год. С 1 января — снова с 1 |
| Начальный номер | Задаёт админ, как у инвойсов («последний использованный номер») |
| Когда выдаётся номер | При «Привязать», все три сразу (вариант B). Номера без напечатанного письма — допустимы |
| Как номер попадает в бланк | Автоматически: система ищет «№ ___» в загруженном бланке. Тегов в файле нет |
| Формат номера | Просто число: `№ 15` |
| Правка начального номера | В любой момент; действует только на новые номера |
| Ручная правка | Номер письма у конкретной продажи можно исправить вручную |

## Design

### 1. Бланк: `ExportFirm.letterhead` (core)

- `letterhead = FileField(upload_to='export_firms/letterheads/', null=True, blank=True)`.
  Nullable — бета со старым кодом на той же базе не ломается.
- Отдаётся и принимается тем же `ExportFirmSerializer` (`export/views_admin.py`) как
  `RelativeFileField`, по образцу `director_stamp`.
- **Проверка при загрузке** (`validate_letterhead`): расширение `.docx`, файл открывается
  python-docx, в теле есть абзац с `№` и за ним `_` (≥3 подчёркиваний, допускается разбиение на
  несколько runs). Иначе 400 с текстом: файл повреждён / не найдено «№ ___».
- **Нет бланка у фирмы → письмо печатается как сейчас.** Бланк другой фирмы (в т.ч. Yigit)
  не подставляется никогда.

### 2. Номера писем (contracts)

**Поля продажи** `ContractSale`: `ct1_number`, `fito_number`, `customs_number` —
`IntegerField(null=True, blank=True)`. Nullable — безопасно для беты.

**Начальные номера** — новая модель `LetterNumberBase`:

| Поле | Тип |
|---|---|
| `export_firm` | FK `core.ExportFirm`, `PROTECT` |
| `letter_type` | `CharField(max_length=10)`, choices `ct1` / `fito` / `customs` |
| `year` | `IntegerField` |
| `last_number` | `IntegerField`, default 0 |
| `updated_at` / `updated_by` | аудит, как у `InvoiceNumberBase` |

`UniqueConstraint(export_firm, letter_type, year)`. Строки нет → граница 0.

**Сервис** `contracts/services/letter_number.py`, по образцу `invoice_number.py`:

```
allocate_letter_number(export_firm_id, letter_type, year) -> int
ensure_letter_numbers(sale) -> ContractSale   # заполняет все пустые из трёх
```

- `get_or_create` + `select_for_update()` строки `(firm, type, year)` — сериализует
  одновременные выдачи. Только внутри `transaction.atomic`.
- Номер = наименьший `n > last_number`, которого нет у продаж этой фирмы (`contract__export_firm`)
  с `invoice_date__year = year` в поле этого вида письма. Освободившийся номер переиспользуется —
  так же, как у инвойсов.
- Год = год `invoice_date`. Если даты нет — та же логика, что у инвойса (дата рейса, иначе сегодня);
  поэтому `ensure_letter_numbers` вызывается **после** `ensure_invoice_number`.
- Продажа закрытого сезона номера не получает (запрет записи D1); письмо печатается без номера,
  «№ ___» остаётся пустым.

### 3. Где выдаются номера

- **«Привязать»** (`link_split_to_contract`): после номера инвойса — `ensure_letter_numbers`.
  Повторное «Привязать» уже выданные номера не меняет.
- **Скачивание письма** — `ContractSaleViewSet.document` (для `ct1_ru` / `fito_ru` / `customs_tk`)
  и `ShipmentPacketZipView` (для каждой продажи пакета): если номера нет — выдать. Покрывает
  старые и ручные продажи.
- **Ручная продажа** (`ContractSaleCreateSerializer.create`) — тоже `ensure_letter_numbers`.

### 4. Ручная правка номера

- Endpoint `PATCH /api/v1/contracts/sales/{id}/letter-numbers/`, тело — любые из
  `{ct1_number, fito_number, customs_number}` (целое ≥ 1).
- Проверка: номер не занят другой продажей той же фирмы, того же года, в том же поле → **400**
  с текстом («№ 15 уже занят …»), не 500. Продажа закрытого сезона — отказ существующего
  `SeasonNotClosed` (как у любой правки продажи).
- Права — те же, что на редактирование продажи (resource `sale`, write).
- Правка начального номера (`LetterNumberBase`) на уже выданные номера не влияет.

### 5. Генерация (`document_render.generate`)

Только для ключей `ct1_ru`, `fito_ru`, `customs_tk`. ZIP-пакет идёт через тот же `generate`,
поэтому изменение действует и на пакет.

1. Письмо рендерится как сейчас (`render_docx`, включая подсветку и `DocumentLayoutSetting`).
2. `generate()` сам берёт фирму-продавца продажи (`sale.export_firm or contract.export_firm`,
   как в builders) и номер из поля продажи; builders и шаблоны не меняются.
3. Если у фирмы есть бланк: открыть его, в абзаце «№ ___» заменить подчёркивания на номер
   (нет номера — оставить подчёркивания), затем вставить тело бланка **в начало** письма
   (`docxcompose.Composer(letter).insert(0, letterhead)`).
4. **Письмо — основной документ**, поэтому его шрифт, поля и настройки макета не меняются
   (проверено прототипом: последняя секция сохраняет поля письма). Побочный эффект, найденный
   прототипом: бланк берёт интервалы стиля Normal письма, растягивается, и ARZA уходит на
   2 страницы. Поэтому перед вставкой свойства абзацев бланка, унаследованные от его стилей
   (интервалы, межстрочный), записываются в абзацы напрямую — бланк выглядит как в Word.
5. Нечитаемый файл бланка на диске → предупреждение в лог, письмо печатается без бланка
   (как `_resolve_stamp`), документ не падает.

### 6. Зависимость от автонумерации инвойсов

Задача 3 плана инвойсов ещё не сделана, поэтому номера писем от неё **не зависят**:
`ensure_letter_numbers` вызывается в тех же точках сам и `invoice_date` не пишет. Год
нумерации = год `invoice_date`, иначе дата рейса, иначе сегодня (`letter_year`); продажа без
`invoice_date` считается «занявшей» номер в году своего рейса. Когда задача 3 инвойсов будет
сделана, она поставит `invoice_date` раньше — правило года от этого не меняется.

### 7. Фронтенд

- **Карточка экспортной фирмы** (`pages/admin/ExportFirmDetailPage.tsx`): загрузка бланка
  (.docx) рядом с печатью и подписью; показать имя текущего файла и ссылку на скачивание;
  замена = новая загрузка. Ошибка проверки — текст с сервера.
- **«Нумерация инвойсов»** (`pages/admin/InvoiceNumberingPage.tsx`): 3 новые колонки
  (СТ-1 / Фито / ARZA) с «последним использованным номером» по фирме за выбранный год.
  Новый admin endpoint по образцу `InvoiceNumberBaseView` (`GET ?year=`, `PUT {export_firm,
  letter_type, year, last_number}`), либо расширение существующего — решается в плане.
- **Раздел «Документы» на странице рейса**: у каждой фирмы рядом с СТ-1 / Фито / ARZA —
  «№ 15» и ✎ для ручной правки; ошибка 400 — текст с сервера.
- i18n en / ru / tk. В UI нет слова «draft/черновик».

## Out of scope

- Заполнение даты в бланке.
- История версий бланка.
- Бланк для инвойса, CMR, контракта.
- Импортные фирмы.

## Testing

- Выдача: первый номер = floor + 1; отдельные счётчики по фирме и по виду письма; новый год
  начинается с 1; освободившийся номер переиспользуется; повторное «Привязать» номер не меняет;
  закрытый сезон номер не получает.
- Ручная правка: свободный номер сохраняется; занятый → 400; закрытый сезон → 400.
- Загрузка: валидный бланк принят; повреждённый файл / без «№ ___» / не .docx → 400.
- Генерация: с бланком — в docx есть текст бланка и номер на месте «№ ___», последняя секция
  с полями письма; без бланка — вывод как раньше; бланк одной фирмы не попадает в письмо другой;
  PDF-смоук (1 страница для всех трёх писем на тестовом бланке).
- Фронтенд: загрузка бланка, колонки нумерации, правка номера.
