# Остаток: расчёт и пересчёт в зале — design

**Date:** 2026-09-26
**Status:** approved in chat, not implemented
**Builds on:** `2026-09-24-gaplama-batch-selection-design.md` (merged as PR #20)

## Problem

Сегодня в системе два независимых понятия «остаток», и они не знают друг о друге.

1. **Расчётный.** `build_gaplama_board` (`backend/apps/export/services/gaplama.py`)
   прогоняет FIFO-обход: неотгруженный план переносится на следующий день и
   протухает через `GreenhouseBlock.carry_days`. Никто его не вводит, он всегда есть,
   и именно он виден на Gaplama — колонка `Geçen` и строка `Galyndy` в форме машины.
2. **Пересчитанный.** `HarvestDayEntry.yesterday_rest_value` («Düýnki galyndy») —
   поле на странице «Ýük plan we galyndy» (`/export/harvest-board`), которое человек
   заполняет руками.

Расчётный может врать: план 20 000, погрузили 15 000, компьютер говорит 5 000 — а в
зале 4 200, потому что часть побилась, или 5 800, потому что собрали сверх плана.

**Пересчитанное поле при этом пустое.** На 2026-09-26: 51 заполненная строка из 4029,
и почти всё — мусор из тестов (23456, 65656, 56656, 8989). Правдоподобных значений
два — 2000 и 1200 за 15–16 сентября. Заполняется только руками, и этого никто не делает.

Так что «показывать остаток из `yesterday_rest_value`» сегодня показало бы пустоту.

## Decisions taken

| Вопрос | Ответ |
|---|---|
| Должен ли человек иметь возможность поправить расчёт? | **Да.** Реальность важнее арифметики. |
| Кто правит? | `loading_dept_head` и его заместитель (плюс admin/boss). |
| Как поле перестаёт быть пустым? | **Компьютер сам пишет туда свой расчёт** ежедневно. |
| Что делает человек с возрастом остатка? | **Ничего.** Владелец 2026-09-26: «для них все остатки вчерашние, они там не делают пометки». Возраст остаётся за компьютером. |
| Остаток по партиям или одной кучей? | **Одной кучей.** Ящики физически перемешаны — решено 2026-09-25, см. PR #20. |

## 1. Кто пишет и когда

Ежедневная задача в `CELERY_BEAT_SCHEDULE` (`backend/config/settings.py:466`).
Не по расписанию крона — на этом проекте пустой crontab уже съедал задачи.

Задача берёт вчерашний день `D-1`, считает `build_gaplama_board` за него и для каждого
блока пишет `carried_out_kg` в `HarvestDayEntry.yesterday_rest_value` строки `(блок, D)`.

**Пишет только туда, где человек ещё не правил.** Признак правки — новое поле
`yesterday_rest_overridden_at` (см. §3): если оно не пусто для этой строки, задача её
не трогает. Иначе ночной прогон затирал бы вечернюю правку начальника.

Строки `HarvestDayEntry` создаются по требованию, как уже делает `daily_board.py`.

Время запуска — после того, как погрузка за день закончена. Точный час подтвердить
у владельца перед реализацией; по умолчанию 23:30 местного.

## 2. Что видит и правит человек

На «Ýük plan we galyndy» колонка «Düýnki galyndy» уже есть. Меняется следующее:

- В ней теперь всегда стоит число — расчёт компьютера, а не пусто.
- Рядом с исправленным значением — пометка, что его правил человек, кто и когда
  (`yesterday_rest_overridden_by`, `_at`). Без этого через неделю никто не отличит
  расчёт от пересчёта.
- Поле редактируют только `loading_dept_head`, `loading_dept_head_deputy` и admin-like.
  Для остальных ролей колонка становится read-only. Сейчас писать может любой, у кого
  есть доступ к странице (`views_daily_board.py:82`); это сужение, а не расширение.
- Кнопка «вернуть расчёт» — снимает правку, чистит три поля, следующий прогон задачи
  запишет туда свежий расчёт.

## 3. Модель

```python
# HarvestDayEntry — рядом с существующим yesterday_rest_value
yesterday_rest_overridden_by = models.ForeignKey(
    'core.User', null=True, blank=True, on_delete=models.SET_NULL,
    related_name='+',
)
yesterday_rest_overridden_at = models.DateTimeField(null=True, blank=True)
```

Само `yesterday_rest_value` не меняется — меняется только то, кто его пишет.

`yesterday_rest_overridden_at IS NULL` означает «это расчёт компьютера»; не NULL —
«человек пересчитал». Третье состояние (пусто) остаётся для дней до внедрения.

## 4. Как Gaplama читает исправленное

`build_gaplama_board` продолжает вести свои корзины по датам — они нужны для протухания.
Меняется одно: в начале дня `D`, если у блока есть правка человека (`_overridden_at`
не пусто), сумма корзин подгоняется под введённое число `R`.

**Возраст при этом человек не задаёт** — он его не знает и не отмечает. Правило:

- **`R` меньше расчётного** — снимаем с **самых старых** корзин, пока сумма не сойдётся.
  Пропавшие ящики — это те, что лежали дольше всех.
- **`R` больше расчётного** — излишек кладём **одной корзиной, датированной `D-1`**.
  Это прямое следствие слов владельца: для зала весь остаток — вчерашний.

Обе ветки сохраняют свойство, на котором держится экран: нигде не может появиться груз
свежее, чем он есть на самом деле.

`carry_in_breakdown` и `age_days` считаются после подгонки, так что подпись
«до N дней» в форме машины остаётся честной.

## 5. Риски

1. **Доска перестаёт сходиться сама с собой.** `Boş` больше не равно
   «перенесено + план − погружено»: в него входит человеческое число. Правило,
   написанное на экране (см. §3 спеки PR #20), придётся переписать, иначе оно будет
   врать. Это осознанный размен, а не побочный эффект.
2. **Защита от превышения меняет смысл.** Она считает от `available_kg`, а тот теперь
   зависит от введённого числа. Если начальник занизил остаток, упаковщик упрётся в
   отказ на грузе, который физически есть. Сообщение про müdir остаётся верным по
   форме, но адресует не туда — его текст надо перепроверить.
3. **Ночная задача и вечерняя правка.** Защита — `_overridden_at`, но она работает
   только если задача действительно её читает. Это первое, что надо покрыть тестом.
4. **Задним числом.** Правка остатка за прошлый день меняет расчёт всех последующих
   дней, потому что обход идёт вперёд. Насколько далеко это допустимо — открытый
   вопрос, см. ниже.

## 6. Тесты

- Задача пишет расчёт в пустую строку; не трогает строку с `_overridden_at`.
- Задача создаёт `HarvestDayEntry` там, где её не было.
- `R` меньше расчётного: снимается со старых корзин, молодые целы.
- `R` больше расчётного: излишек датирован `D-1`, не сегодняшним днём.
- `R = 0`: блок показывает остаток 0, а не расчётный.
- Роль без гранта получает 403 на запись в поле, но видит его.
- «Вернуть расчёт» чистит три поля; следующий прогон задачи пишет туда расчёт.
- Правка за день `D` меняет `available_kg` дня `D+1`.
- Существующие тесты `tests_gaplama_board` и `tests_gaplama_carry_days` должны
  пройти **без изменений**: без правок поведение прежнее.

## Out of scope

- **Что делать, когда план не материализовался** (план 36 000, собрали 3 000) —
  отложено владельцем 2026-09-25. Смежная тема, но отдельная.
- **История правок.** Хранится только последняя, кем и когда. Полный журнал — в
  `AuditLog`, если понадобится, но отдельной страницы истории нет.
- Возраст остатка, вводимый человеком. Он его не отмечает.

## Открытый вопрос для владельца

Насколько далеко назад можно править остаток? Правка за прошлый понедельник
пересчитает всю неделю, включая дни, по которым машины уже уехали. Варианты:
только вчера; в пределах текущей недели; без ограничений. Подтвердить до реализации.
