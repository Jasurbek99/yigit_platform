## 3. Структурные конфликты: без решений по ним нельзя писать спек для PREP и DOCS

1. **Зависимости «после N».** Сейчас задачи создаются по статусу. Правила «задача после задачи» нет: `Task.blocked_by` существует, но движок его не пишет. Дорожная карта 2026-09-24 ставит зависимости (A) **после** редактора правил. Редактор не сделан. Если строить зависимости сейчас, это ломает утверждённый порядок.
2. **Границы фаз через задачи.** Фаза DOCS состоит почти целиком из кнопок и «напечатал». Задачи `MANUAL_DONE` не держат авто-переход статуса (`is_step_trigger_satisfied` их исключает). Значит, шаг из одних кнопок никогда не перейдёт дальше сам. Нужна правка движка, а не только новые строки в seed.
3. **Статусов меньше, чем фаз в списке.** PREP = `draft`, DOCS = `gumruk_girish` + `gumruk_chykysh`. Двадцать задач 9–22 надо разложить по этим двум шагам или по новым.
4. **Чужие работы.** 23 и 27 делает сессия garawul. 6 пересекается со спеком packaging-join. Для 3 и 8.1 нет записи «транспортная часть». Для 11 (regular) нет модалки печати. Для 37 нет процесса утверждения.
