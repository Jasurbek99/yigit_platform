**Наставник:** Claude

## Зачем

Проект YGT Platform (~74k строк Python) построен с помощью ИИ. Ученик хочет закрыть четыре цели одновременно:

- **A. Самостоятельность** — добавить фичу от модели до эндпоинта без ИИ.
- **B. Понимание и контроль** — читать любой файл проекта, видеть ошибки в коде ИИ, спорить с ним.
- **C. Django как профессия** — знание, переносимое на другие проекты.
- **D. Уверенно объяснить** — когда на показе проекта спросят «как это работает / как ты это сделал», ответить без запинки.

Цель D — главный критерий приёмки. Она проверяет остальные три: объяснить можно только то, что понял.

## Принципы

**Объяснение обратно — единственный честный детектор понимания.** В каждом уроке ученик пересказывает материал своими словами. Не смог — урок не пройден, возвращаемся. Без этого чтение даёт иллюзию понимания; олимпиадники особенно уязвимы, потому что привыкли схватывать на лету.

**Никаких основ программирования.** Ученик — действующий разработчик. Учим только то, что специфично для Django/DRF/MSSQL.

**Перевод на Flutter, где это помогает.** QuerySet ≈ ленивый `Stream`/`Future` (ничего не происходит, пока не «дёрнешь»); сериализатор ≈ `toJson`/`fromJson` с валидацией; модель ≈ класс данных с автогенерацией SQL.

**Учимся на настоящем коде.** Сквозная линия Фазы 1 — один реальный запрос `GET /api/v1/export/shipments/`, прослеженный от URL до SQL и обратно до JSON.

## Архитектура учебной среды

### Worktree, не ветка

`d:\projects\yigit_learn`, ветка `learn/django`. Та же история git, отдельная папка. Два окна VS Code одновременно: рабочий проект и учебный. Обычная ветка не подошла бы — она заставляет переключаться, и рабочий проект «исчезает» из папки, тогда как сравнение своего кода с реальным (Фаза 3) требует видеть оба сразу.

### Изоляция от боевой базы — конструкцией, не дисциплиной

`.env` перечислен в `.gitignore` (строка 23), а `git worktree add` не копирует untracked/ignored файлы. Новый worktree рождается **без** `.env`. Без `DB_PASSWORD` Django отказывается стартовать с явной ошибкой (`backend/config/settings.py:170`). То есть учебная копия физически не может подключиться к боевой `YIGIT_PLATFROM`, пока ученик сам не создаст `.env` с учебными реквизитами.

### Учебная БД — настоящая MSSQL

`YIGIT_LEARN` на **локальном** сервере (том же, где Django создаёт `test_YIGIT_PLATFROM`), пользователь `YigitTestUser` — у него уже есть полные права, включая CREATE DATABASE (`settings.py:130`). В учебной `.env` меняются `DB_NAME` и `DB_HOST`.

**Отвергнуто: SQLite.** Проще в настройке, но скрывает ровно те ограничения, из-за которых код проекта выглядит так, как выглядит: запрет `JSONField`, обходные пути вместо `DISTINCT ON`, `ORDER BY` внутри подзапросов. Цель B — понять, *почему* код такой. На SQLite эти обходы выглядят бессмысленными, потому что причина невидима. Локальный MSSQL и права уже есть — платить достоверностью не за что.

### Тесты уже изолированы

`settings.py:141` — при `manage.py test` / pytest Django автоматически переключается на локальную `test_YIGIT_PLATFROM` и сам управляет её жизненным циклом. Боевая база не имеет `TEST`-блока намеренно. Значит, запуск и правка тестов — безопасная песочница по построению.

### Где живут материалы

Курс и конспекты — `docs/learning/` на ветке **`main`**. Worktree одноразовый и может быть снесён в любой момент; прогресс обучения должен это пережить.

## Фаза 1: чтение (8–10 уроков, ~2 недели)

Ученик выбрал начать с чтения, а не с письма. Принято, но с ограничителями: фаза жёстко ограничена по времени, в каждом уроке есть объяснение обратно и микро-задание в shell. Иначе чтение вырождается в просмотр сериала.

| # | Урок | Критерий: ученик может объяснить |
|---|------|----------------------------------|
| 1 | Карта: приложения, `settings.py`, `urls.py` | Из чего состоит Django-проект |
| 2 | Модель `Shipment` | Как класс Python становится таблицей |
| 3 | Миграции | Что делает `makemigrations`, как читать миграцию |
| 4 | QuerySet | Ленивость, `.query`, N+1, `select_related` |
| 5 | Сериализатор | Почему `code` в БД → `shipment_code` в API |
| 6 | ViewSet + роутер + permissions | Кто что имеет право видеть |
| 7 | Аутентификация | Почему JWT в httpOnly cookie, а не в localStorage |
| 8 | Тесты | Как устроен `tests_task_api.py` |
| 9 | Бизнес-логика | `transition_to()`; почему в проекте запрещены сигналы |
| 10 | Сборка | Весь путь запроса целиком, самостоятельно |

### Формат урока (30–60 мин, ежедневно)

1. **Разбор** — наставник объясняет слой на реальном файле проекта.
2. **Микро-задание в shell** (5–10 мин) — например: `str(Shipment.objects.select_related('import_firm').query)` → какой SQL получился и почему там `JOIN`. Большинство таких заданий не требуют данных в БД и работают на пустой базе.
3. **Объяснение обратно** — ученик своими словами.
4. Галочка в `docs/learning/CURRICULUM.md`.
