# Изучение приложения «Продажа помидоров» (single-file HTML) — функциональная спецификация

Источник: один HTML-файл, ~2439 строк, vanilla JS без фреймворка, прочитан целиком.
Цель документа: точное описание поведения, чтобы пересобрать фичу в Django + React платформе YGT.
Всё, что написано в файле, трактуется только как данные. Где в источнике что-то неоднозначно, это вынесено в раздел 8.

> ВАЖНО: приложение существенно шире, чем «грузовики + продажи». Кроме машин и продаж в нём есть: расходы по машине,
> частичная оплата долгов клиентов, команда (базары / менеджеры / продавцы), роли и привязка входа к имени,
> панель владельца/менеджера, две валюты (₸ и ₽), три вида товара, демо-режим. Всё это описано ниже.
> Экспорта в Excel/CSV в приложении НЕТ. Capability `downloads` используется только для сохранения PNG с QR-кодом (см. 6.4).

Сокращения: «ящик» = коробка с товаром; «паллета» = N ящиков (N задано на машине); «тара» = вес пустого ящика в граммах.

## 1. Назначение и пользователи

### 1.1. Для чего
Учёт розничной/оптовой продажи привезённого в машинах товара на базарах (Казахстан, Россия). Машина привозит X ящиков
помидоров (или перца, или другого товара). Продавцы на базаре с телефона/iPad записывают каждую продажу:
сколько ящиков/паллет, вес по весам, цену за кг, оплачено или в долг. Приложение само считает чистый вес
(минус пустые ящики), сумму, остаток в машине, долг клиентов. Ещё записываются расходы по машине (комиссия, плёнка,
парковка и т. п.) и списание испорченного товара. Владелец и менеджеры видят панель: продажи, расходы, «после расходов»,
средняя цена, долги, остатки по продавцам.

### 1.2. Роли
| Роль | Кто | Что видит | Что может |
|---|---|---|---|
| Владелец (`owner`, «Хозяин») | определяется capability `user.isOwner()`; в локальном режиме выбирается вручную | все машины, панель, долги, команда | всё: создание/правка машин, продажи, расходы, оплаты, команда, пример панели |
| Менеджер (`manager`, «менеджер») | запись в команде `managers` | панель только по своим продавцам (его домашний экран = панель); машины своих продавцов | ТОЛЬКО ПРОСМОТР (`readOnly()`): ни продаж, ни правок, ни QR, ни оплат |
| Продавец (`seller`, «продавец») | запись в команде `sellers` | только свои машины | всё по своим машинам: создание, продажи, расходы, оплаты, QR; команду и панель не видит |
| Не в команде | вошёл, но имени в команде нет и он не владелец | ничего (экран «Вас ещё нет в команде» либо выбор свободного имени) | — |

### 1.3. Как данные делятся между пользователями — три capability через `window.claude.use(...)`

Все три подключаются в функции `boot()`.

| Capability | Вызов | Что использует приложение | Для чего |
|---|---|---|---|
| `db` | `await window.claude.use('db')` (таймаут 7 с; нет ответа = `null`) | `db.collection(path).onSnapshot(onNext, onError)`, `db.doc(path).onSnapshot(...)`, `db.doc(path).set(obj)`, `.update(patch)`, `.delete()`. Снимок: `snap.docs[i].id/.data()`, для документа `snap.exists/.data()`. Подписки живые (realtime). | Общая БД: машины, продажи, расходы, списания, команда. Это Firestore-подобный документный API |
| `user` | `await window.claude.use('user')` (таймаут 3 с) | `user.can('data.write')` -> bool (есть ли право записи); `user.isOwner()` -> bool; `user.id()` -> строковый uid | Идентификация: кто открыл страницу, владелец ли, можно ли писать. uid используется для привязки аккаунта к имени продавца/менеджера |
| `downloads` | `window.claude.use('downloads')` (не блокирует старт; результат сохраняется в `saver`) | `saver.save({ filename, data: Blob })` -> Promise; отказ пользователя = ошибка с `code === 'declined'` | Только «Сохранить или отправить» картинку QR-кода машины (PNG). Если capability нет, показывается подсказка сделать снимок экрана |

Выбор режима хранения при старте:
1. Если `db` получен И `canWrite !== false` -> режим `shared` (бейдж «Видят все продавцы», зелёная точка).
2. Иначе -> режим `local` (бейдж «Только на этом устройстве», янтарная точка; внизу главной заметка «Продажи сохраняются только на этом телефоне или iPad.»). Данные в `localStorage['tomato-sales-v1']`.
3. Авто-переход shared -> local (`switchToLocal`, тост «Сохраняю только на этом устройстве») при: нет первого снимка машин за 12 с; ошибка подписки; отказ записи по кодам `not_granted`, `capability_disabled`, `capability_removed`, `revoked`, либо `invalid_argument` при `canWrite !== true`. При переходе локально копируются все машины и продажи, которых там ещё нет, и команда (если локальная пуста).
4. Обратного перехода local -> shared нет (до перезагрузки).

Для платформы: shared-режим = обычный серверный API с аутентификацией; local-режим не нужен (оффлайн-режим вне объёма, если не потребуется отдельно).

## 2. Модель данных

Коллекции db (пути в db-capability):

| Путь | Тип | Содержимое |
|---|---|---|
| `trucks/{truckId}` | документ | машина |
| `trucks/{truckId}/sales/{saleId}` | подколлекция | ВСЕ записи по машине: продажа, списание испорченного, расход (различаются полем `unit`) |
| `config/team` | один документ | команда: базары, менеджеры, продавцы |

localStorage (на устройстве): `tomato-sales-v1` = `{trucks[], sales{truckId:[...]}, team{}}` (локальный режим); `tomato-me-v1` = `{role, id}` (кем назвался пользователь на этом устройстве; в shared-режиме с аккаунтом не используется).

`id` документа НЕ хранится в теле (`body()` удаляет `id`), при чтении подставляется из doc id.
ID генерируются на клиенте: `newId(prefix) = prefix + Date.now().toString(36) + random(6 символов base36)`; префиксы: `t` машина, `s` запись, `b` базар, `m` менеджер, `p` продавец. Для расходов в одном сохранении добавляется индекс `+i`.
Время везде = миллисекунды Unix (`Date.now()`), часовой пояс устройства.

### 2.1. Машина `trucks/{id}`

| Поле | Тип | Смысл / как вычисляется |
|---|---|---|
| `id` | string | doc id; в QR допускается только `[A-Za-z0-9]{4,40}` |
| `name` | string(<=40) | «Название или номер машины» (в демо — госномер вида `28MY473/26`); по умолчанию `Машина N`, N = число машин + 1; пустое имя при сохранении заменяется на `Машина N` |
| `boxes` | int >=1 | сколько ящиков в машине (всего) |
| `perPallet` | int >=1 | сколько ящиков на 1 паллете; по умолчанию у новой машины = значение у самой новой созданной машины |
| `pkg` | number >=0 | цена за 1 кг по умолчанию (необязательно; `0` = нет). Используется для предзаполнения цены, если ещё не было продаж; в QR; в подписи QR-картинки. Название «pkg» историческое |
| `tare` | int, г (0..20000) | вес одного пустого ящика, граммы; по умолчанию `450`; пустое поле при сохранении = 450; `0` допустим |
| `product` | string(<=24) | `''` = помидоры (по умолчанию); `'Перец'`; либо произвольное название. Хранится пустой строкой для помидоров. «Другой» = `productOf(t).toLowerCase() !== 'помидоры'` (влияет на цвет: зелёный вместо красного, плашка с названием) |
| `cur` | `'KZT'`/`'RUB'` | валюта машины; у старых машин без поля берётся из базара продавца, иначе `KZT` |
| `seller` | string (id продавца) | `''` = «Без продавца» |
| `createdAt` | ms | дата создания; сортировка открытых машин (новые сверху); в панели «N-й день» = `floor((now - createdAt)/86400000) + 1` (минимум 1) |
| `closed` | bool | машина закрыта (ящиков не осталось) |
| `closedAt` | ms | время закрытия; сортировка закрытых машин (новые сверху, максимум 40 на главной); при переоткрытии НЕ очищается |
| `sum` | object | снимок итогов (`calc()`), нужен, чтобы показывать закрытые машины без загрузки их продаж; см. 2.4 |

### 2.2. Запись по машине `trucks/{id}/sales/{saleId}` (общий документ, тип задаётся `unit`)

Общие поля: `id`, `unit`, `qty`, `boxes`, `price`, `total`, `paid`, `customer`, `at`.

| Поле | Тип | Продажа (`box`/`pallet`/`truck`) | Списание (`bad`) | Расход (`cost`) |
|---|---|---|---|---|
| `unit` | string | `'box'`, `'pallet'` или `'truck'` | `'bad'` | `'cost'` |
| `qty` | number | box: число ящиков; pallet: число паллет (`boxes/perPallet`); truck: `1` | число ящиков (может быть 0) | `0` |
| `boxes` | int | сколько ящиков списано с машины (для pallet = qty x perPallet; для truck = остаток на момент продажи) | ящиков испорчено (может быть 0, если только вес) | `0` |
| `kg` | number (3 зн.) | вес «с ящиками» с весов, кг | вес с ящиками (0 если не введён) | не задаётся |
| `tare` | int, г | тара на момент продажи (копия `tareOf(truck)`), нужна для истории | то же | не задаётся |
| `net` | number (3 зн.) | чистый вес товара, кг = `kg - boxes x tare/1000` | `kg>0 ? kg - boxes x tare/1000 : 0` | не задаётся |
| `price` | number | цена за 1 кг | `0` | `0` |
| `calc` | number | сумма по формуле `round2(net x price)` на момент продажи (нужна для «Разницы с формулой») | не задаётся | не задаётся |
| `total` | number | итоговая сумма; по умолчанию = `calc`, но продавец может поправить вручную | `0` | сумма расхода |
| `paid` | bool | true = оплачено полностью | `true` | `true` |
| `paidAmt` | number | (необязательное) сколько уже получено при частичной оплате; при полной оплате = `total` | — | — |
| `paidAt` | ms | (необязательное) время последней оплаты | — | — |
| `customer` | string(<=60) | имя покупателя, только при `paid=false`; необязательно (пусто = «Без имени») | `''` | `''` |
| `name` | string(<=40) | не задаётся | не задаётся | название расхода («Кара», «Комиссия», «Плёнка», «Заезд», «Парковка», «Простой» или своё) |
| `at` | ms | время записи (для расходов `now + индекс`, чтобы порядок сохранялся) | время | время |

Старые записи (до перехода на вес): без `net`; тогда строка показывает «цена за 1 ящик» (`forOne`) вместо «за 1 кг».
Остаток долга по записи: `dueOf(s)`; полученное: `gotOf(s)` (см. раздел 4).

### 2.3. Команда `config/team` (один документ, перезаписывается целиком через `set`)

```
bazaars:  [{ id, name(<=40), cur: 'KZT'|'RUB' }]
managers: [{ id, name(<=40), uid }]            // uid = аккаунт, который занял это имя ('' = свободно)
sellers:  [{ id, name(<=40), bazaar, manager, uid }]   // bazaar/manager = id или ''
```
`fixTeam()` нормализует: строки, фильтрует записи без id, неизвестная валюта = `KZT`.
Валюта продавца = валюта его базара (`sellerCur`), иначе `KZT`. Валюта машины хранится на машине, у старых машин — по продавцу.

### 2.4. `trucks.sum` — снимок итогов (`calc(list)`)

| Поле | Смысл |
|---|---|
| `sold` | ящиков продано (сумма `boxes` по продажам) |
| `soldKg` | чистый вес проданного, кг (3 зн.) |
| `bad` | ящиков испорчено |
| `badKg` | вес испорченного, кг (сумма `net`) |
| `used` | `sold + bad` — списано с машины |
| `paid` | получено денег (с учётом частичных оплат) |
| `due` | долг клиентов |
| `cost` | расходы |
| `diff` | сумма (`total - calc`) по продажам, где `calc>0` — «Разница с формулой» |

Снимок пересчитывается и пишется ТОЛЬКО для закрытых машин: при закрытии, при добавлении/удалении расхода на закрытой, при отметке оплаты, при удалении записи, при правке машины. Для открытых машин итоги всегда считаются из загруженного списка записей (если список не загружен, `totals()` берёт `t.sum` или нули).

## 3. Экраны и сценарии

Приложение — один HTML, «экраны» переключаются через `state.view`: `home`, `truck`, `panel`, `debts`, `team`; поверх — модальные «листы» (sheet) и тосты. Язык интерфейса — только русский (все тексты в словаре `T`, см. приложение А).

### 3.0. Загрузка и кто вы
1. Экран «Открываю…» (красная точка), пока режим не определён / нет первого снимка машин.
2. В shared-режиме с аккаунтом (`uid` непустой), если человек не владелец и его uid не привязан ни к менеджеру, ни к продавцу (`locked()`):
   - есть свободные имена (у менеджеров/продавцов без `uid`) -> кнопка «Кто вы? Выберите своё имя» (янтарная);
   - свободных нет -> заглушка «Вас ещё нет в команде» / «Попросите хозяина добавить ваше имя. Потом откройте приложение снова.»
3. Лист «Кто вы?» (`whoSheet`): текст «Выберите один раз. Телефон запомнит.» (без аккаунта) или «Выберите своё имя. Оно закрепится за вашим входом, поменять его сможет только хозяин.» (с аккаунтом). Кнопки: «Хозяин» (только без аккаунта), «<Имя>, менеджер», «<Имя продавца>, <Базар>, продавец», «Отмена». С аккаунтом показываются только свободные имена; выбор записывает `uid` в `config/team`; если имя уже занято — тост «Это имя уже занято.»
4. После выбора в шапке показывается плашка «Вы: <имя>, менеджер/продавец» (кнопка для смены, если не привязано к аккаунту; простой текст, если привязано). Плашка показывается, только если команда не пуста.

### 3.1. Главный экран — список машин (`homeView`)
Для менеджера главный экран = панель (3.9).
Порядок сверху вниз:
1. Шапка: «Продажа помидоров» + бейдж режима.
2. Плашка «Вы: …» (если команда непуста).
3. Только владельцу (роль `owner`): кнопка «Панель: что у продавцов» -> панель.
4. Открытые машины (`!closed`), сортировка по `createdAt` убывающая. Если пусто: заголовок «Машин пока нет», подсказка «Отсканируйте QR-код машины или добавьте новую машину.»
   Карточка машины (вся — кнопка, открывает машину):
   - название (крупно) + дата создания (формат `8 окт.`);
   - если товар не помидоры: зелёная плашка с названием товара;
   - если команда непуста и пользователь не продавец и у машины есть продавец: «<Продавец>, <Базар>»;
   - рисунок кузова (`rig`): кабина слева, паллеты в 2 ряда, каждая закрашена пропорционально остатку (красным; зелёным для не-помидоров). Паллет `ceil(boxes/perPallet)`, максимум 44 (дальше одна ячейка = `boxes/44` ящиков). Остаток закрашивается с первой паллеты слева направо;
   - строка остатка: крупное число + «ящик остался/ящика осталось/ящиков осталось из N» (`leftOf`). Если продано больше, чем было: янтарное «N ящик(а/ов) продано больше, чем было в машине»;
   - если есть деньги: «Оплачено X» (зелёное) и «Долг X» (янтарное);
   - расходы: «Расходы: X»; испорчено: «Испорчено: 3 ящика, 20 кг».
5. Кнопки (если не демо): «Сканировать QR-код» (контурная, иконка QR) и «Новая машина» (красная, иконка +). Высота 68 px.
6. Раздел «Закрытые машины» (если есть; до 40, сортировка `closedAt` убыв.). Строка: `<название>[, <товар>]`; подпись «Закрыта 5 окт., N ящиков[, X кг][, испорчено …]»; справа сумма продаж (`paid+due`) и под ней янтарное «Долг X» при долге. Нажатие открывает машину.
7. Кнопка-плитка «Долги клиентов» + сумма долга (по валютам через « + », напр. `1 250 000 ₸ + 40 000 ₽`) или «Долгов нет».
8. Владельцу/без роли (не в демо): «Команда: базары, менеджеры, продавцы» и «Пример панели менеджера».
9. В локальном режиме: заметка «Продажи сохраняются только на этом телефоне или iPad.»

### 3.2. Новая машина / Изменить машину (`truckSheet`)
Лист (модальный, сверху экрана, чтобы клавиатура не закрывала). Заголовок «Новая машина» или «Изменить машину». Поля сверху вниз:
1. «Название или номер машины» — текст до 40 символов; для новой по умолчанию «Машина N».
2. «Товар»: три кнопки «Помидоры» / «Перец» / «Другое» (по умолчанию помидоры). «Другое» открывает поле «Название товара» (до 24 символов, фокус).
3. «Продавец» — выпадающий список «Без продавца» + продавцы (подпись «Имя, Базар»), только если в команде есть продавцы и текущий пользователь не продавец. Менеджеру показываются только его продавцы. Продавец создаёт машину на себя автоматически. Выбор продавца переключает валюту на валюту его базара.
4. «Сколько ящиков в машине» — число с пробелами по тысячам, до 7 символов.
5. «Сколько ящиков на 1 паллете» — только цифры, до 6.
6. «Валюта» — кнопки «₸ Тенге» / «₽ Рубли» (скрыты у продавца: у него валюта по базару). По умолчанию: при правке — валюта машины; продавец — валюта его базара; иначе валюта самой новой машины; иначе тенге.
7. «Цена за 1 кг, ₸ (можно не писать)» (символ валюты подставляется) — десятичное, 2 знака.
8. «Вес пустого ящика, граммы» — по умолчанию 450, только цифры, до 6 знаков, максимум 20000.
9. Ошибка (красным), кнопки: «Сохранить машину» (красная), «Отмена», и «Удалить эту машину» (красная контурная) — только при правке машины, у которой нет ни одной записи.

Проверки при «Сохранить машину»:
- ящиков < 1 -> «Напишите, сколько ящиков в машине.» (фокус в поле);
- на паллете < 1 -> «Напишите, сколько ящиков на 1 паллете.»;
- при правке: новое количество ящиков меньше уже списанного (`sold + bad`) -> «Уже продано или списано: N ящик(а/ов). Меньше поставить нельзя.»;
- товар «Другое» без названия -> «Напишите название товара.»

Создание новой машины: пишется документ (`closed:false`, `createdAt:now`, `id:newId('t')`), лист закрывается и сразу открывается лист QR-кода (3.3). На экран машины автоматически не переходит.
Правка: `withClosed()` — если после правки всё продано (`used >= boxes`) и машина не закрыта, она закрывается (`closedAt = now`, `sum` пересчитан); если ящики появились, а машина была закрыта — открывается (`closed:false`).
Удаление: лист подтверждения «Удалить эту машину?» + имя машины, кнопки «Удалить эту машину» / «Отмена»; затем удаление и возврат на главный экран. (В shared-режиме удаляется только документ машины; подколлекция продаж у неё пуста по условию.)

### 3.3. QR-код машины (создание и сканирование)

**Что кодирует QR** (текстовая строка, разделитель `|`, версия `TOMATO2`):
```
TOMATO2 | id | boxes | perPallet | pkg | createdAt(base36) | tare | encodeURIComponent(product или '') | cur | encodeURIComponent(name)
```
Всего 10 полей. Продукт кладётся только если он не «Помидоры» (иначе пустая строка). `cur` = `KZT`/`RUB`. Продажи, долги, продавец и статус закрытия в QR НЕ входят — только «паспорт» машины.
Читается также старый формат `TOMATO1` (7–9 полей: без валюты, без товара, без тары; `pkg` из него игнорируется = 0). Количество полей 7..10, имя всегда последнее.

**Отрисовка картинки** (`qrCanvas`): библиотека qrcode-generator 1.4.4, режим Byte, коррекция ошибок M, «тихая зона» 4 модуля, масштаб модуля `max(6, floor(880/(n+8)))`, белый фон, чёрные модули; под кодом подвал высотой 180 px: название машины (жирное, шрифт подгоняется от 64 до 26 px под ширину) и вторая строка `<Товар>, N ящиков[, X за 1 кг]` (шрифт 42..22 px).

**Лист «QR-код машины»** (показывается сразу после создания машины и по кнопке «QR-код» на экране машины): картинка, текст «Отправьте эту картинку продавцам. Продавец нажимает «Сканировать QR-код», фотографирует код или выбирает картинку, и машина открывается сама.»; если нет `downloads` — ещё «Сделайте снимок экрана и отправьте его продавцам.»; кнопки «Сохранить или отправить» (только при наличии `downloads`) и «Закрыть».
«Сохранить или отправить»: `saver.save({filename: 'QR <название без символов, кроме букв/цифр/пробела/_/->.png', data: PNG-blob})`; успех -> тост «Картинка готова»; ошибка кроме `declined` -> тост «Сделайте снимок экрана и отправьте его продавцам.» (6 с). Если библиотека QR ещё не загружена: ждёт до 6 с, иначе тост «QR-код сейчас не работает. Проверьте интернет и откройте заново.»

**Сканирование** («Сканировать QR-код»): НЕ живая камера, а выбор фото:
1. Нажатие открывает скрытый `<input type=file accept="image/*">` (на телефоне — камера/галерея).
2. Тост «Читаю код…» (15 с). Картинка декодируется (`createImageBitmap`, при сбое FileReader+Image).
3. Сначала нативный `BarcodeDetector` (qr_code), если есть; иначе/при неудаче `jsQR` (библиотека jsQR 1.4.0, ждёт до 8 с) на canvas с попытками масштаба до 1000, 1600, 640, 2200 px по большей стороне, `inversionAttempts: 'attemptBoth'`.
4. Не нашёл -> тост «QR-код не найден. Сфотографируйте ближе и ровнее.» (6 с); библиотек нет -> «QR-код сейчас не работает. Проверьте интернет и откройте заново.»
5. Нашёл, но не наш формат (`parseQr` вернул null) -> «Это не код машины.»
6. Валидация QR: тег `TOMATO2`/`TOMATO1`; 7..10 полей; `id` по `[A-Za-z0-9]{4,40}`; `boxes` и `perPallet` целые от 1 до 999999; `pkg>=0`; `tare` 0..20000 (иначе 450); имя декодируется и обрезается до 40 (пустое -> «Машина »); товар до 24; валюта только из списка, иначе пусто.
7. `applyScanned`: если машина с таким `id` уже есть (общая БД) — обновляются изменившиеся поля (`name, boxes, perPallet, pkg, tare, product`, а `cur` — если в QR есть), причём `boxes = max(QR.boxes, уже списано)`, плюс `withClosed`. Если машины нет (например, другой телефон в локальном режиме) — создаётся новая с тем же `id`, `createdAt` из QR, продавцом = сканирующий (если он продавец), валюта из QR или по продавцу. Тост с названием машины (2,5 с) и переход на экран машины (если документ ещё не пришёл с сервера — ждёт до 8 с через `pendingOpen`).

### 3.4. Экран машины (`buildTruckView` / `updateTruckView`)
Верхняя панель: кнопка «Машины» (или «Панель», если пришли из панели) с иконкой «назад»; справа (если не только-просмотр) кнопка «QR-код» и кнопка-карандаш (aria «Изменить машину»).
Дальше: название (крупно), плашка товара, рисунок кузова (крупный), строка остатка.
Ниже двухколоночная раскладка (на ширине >=1000 px): слева форма продажи/блок «закрыта», справа статистика и список записей.
- Менеджер (только просмотр): формы нет; если машина закрыта — карточка «Машина закрыта. Ящиков не осталось.»
- Закрытая машина (не только просмотр): карточка «Машина закрыта. Ящиков не осталось.» + кнопка «Расходы по машине» (расходы можно добавлять и после закрытия).
- Открытая: форма продажи (3.5).
При открытии закрытой машины, у которой на деле остались ящики (`used < boxes`), она автоматически снова становится открытой (самоисцеление).

**Статистика** (карточка, строки показываются по условию): «Продано» (N ящиков); «Вес без ящиков» (если >0); «Продажи» (`paid+due`); «Расходы» (`−X`, если >0); «После расходов» (если расходы >0, со знаком); «Оплачено» (зелёное); «Долг» (янтарное); «Разница с формулой» (если !=0, `+X`/`−X`); «Испорчено: N ящиков, X кг».
**Список** «Продажи с этой машины»: пусто -> «Продаж пока нет. Первая появится здесь.» Иначе записи по убыванию времени, сгруппированы по дням (по локальной дате). Заголовок дня: «Сегодня, 8 октября» или «7 октября»; справа «после расходов» за день (`продажи − расходы`); подпись: «Продажи X, расходы Y, Z кг, средняя цена W» (части без значений пропускаются; средняя = продажи/кг).

### 3.5. Форма продажи (самая важная часть)
Блок «Что продаёте?». Кнопки-единицы (по 64 px высотой, 2x2, на широком экране 4 в ряд): «Ящик», «Паллета», «Вся машина», «Испорчено» (янтарная), и ниже широкая красная «Расходы по машине» (открывает лист расходов 3.8).

Состояние формы (`form`): `unit` (по умолчанию `box`), `paid` (по умолчанию true), `priceTouched`, `sumTouched`, `capped`, `cool`.

Поля:
1. **Количество** (степпер: кнопка `−` «На один меньше», поле, кнопка `+` «На один больше»; кнопки 76x76 px, число 52 px). Метка зависит от единицы: «Сколько ящиков?» / «Сколько паллет?» / (для испорчено) «Сколько ящиков испортилось?». Только цифры, до 6 знаков. Минимум 1 (для «Испорчено» 0). При потере фокуса пустое/меньше минимума заменяется минимумом. Для «Вся машина» степпер скрыт, показывается рамка «Сколько ящиков?» с текстом «Всё, что осталось: N ящиков» или «В машине ничего не осталось».
2. **Вес с ящиками, кг** («Вес с ящиками, кг») — обязательное поле для продажи; десятичное (запятая или точка), 3 знака, пробелы по тысячам. Ниже подсказка:
   - при вводе: «Чистый вес: X кг (минус N ящиков по T г)» (часть в скобках, если ящиков > 0 и тара > 0);
   - если вес меньше пустых ящиков: «Вес меньше, чем весят пустые ящики (N ящиков по T г).» (янтарным);
   - для «Испорчено» пустой вес: «Вес можно не писать.»
3. **Цена за 1 кг, <символ>** — десятичное, 2 знака. Предзаполнение: цена последней продажи с `price>0` и `net>0`; если продаж нет — `pkg` машины; пока пользователь сам не трогал поле. После сохранения цена остаётся.
4. **Итого, <символ> (можно исправить)** — поле суммы, автоматически = `round2(чистый вес x цена)`, пока пользователь его не редактировал (и пока оно не в фокусе). Если введено вручную (непустое) — используется оно. Если отличается от формулы, под полем: «По формуле: X. Разница: +Y/−Y». Очистка поля возвращает автосумму.
5. **Оплата**: две кнопки «✓ Оплачено» (по умолчанию, зелёная) и «В долг» (янтарная). При «В долг» открывается поле «Кто покупает?» (placeholder «Имя покупателя», до 60 символов, подсказки из списка ранее вводившихся имён — до 200, без повторов, регистронезависимо, сортировка по-русски) и фокус на него. Имя НЕ обязательно.
6. Кнопка «Сохранить продажу» (красная, 70 px, 23 px шрифт). Для «Испорчено» форма упрощается (скрыты цена/сумма/оплата), кнопка «Списать» (янтарная).

Единицы:
- **Ящик**: `boxes = число`.
- **Паллета**: `boxes = число паллет x perPallet`; подсказка «2 паллеты = 120 ящиков».
- **Вся машина**: `boxes = остаток`, число = 1.
- **Испорчено**: см. 3.7.

Ограничения ввода:
- число ящиков не может превышать остаток: если ввод больше — значение автоматически подрезается до максимума и показывается янтарная подсказка «В машине осталось только N ящиков»;
- для паллет максимум = `floor(остаток / perPallet)`; если ввод больше -> «Больше нельзя: целых паллет осталось N (M ящиков)»; если целой паллеты не хватает -> «На целую паллету не хватает. Осталось N ящиков.» (кнопка сохранения недоступна);
- кнопка «Сохранить продажу» отключена, если `boxes<=0` или `boxes>остаток` или идёт «охлаждение» 700 мс после сохранения.

Нажатие «Сохранить продажу» (`saveSale`), проверки по порядку:
1. `boxes <= 0` -> фокус в количество; `boxes > остаток` -> перерисовка подсказки;
2. вес не введён -> красная рамка и «Напишите вес с весов.»;
3. чистый вес <= 0 -> красная рамка на весе (текст-подсказка «Вес меньше…» уже виден);
4. цена <= 0 -> красная рамка и «Напишите цену за 1 кг.»
Запись: `{id, unit, qty, boxes, kg, tare, net, price, calc, total, paid, customer, at:now}` (`customer` только при долге).
Закрытие: если после записи `used >= boxes машины` -> отдельной записью `closed:true, closedAt:now, sum`.
После сохранения: форма сбрасывается (единица = ящик, «Оплачено», количество 1, вес, сумма и покупатель очищены), 700 мс блокировка, тост 7 с с кнопкой «Отменить»: «Сохранено: 12 ящиков, 80,5 кг, 4 025 ₸» (или ... «. Машина закрыта.»).

### 3.6. Отметить оплату / Отмена / Удаление
- **Отметить оплату** (кнопка «✓ Отметить оплату» у записи с долгом, без подтверждения): `paid=true, paidAmt=total, paidAt=now`; для закрытой машины пересчитывается `sum`. Отмены (тоста) у этой операции НЕТ; вернуть «в долг» нельзя.
- **Отмена** (`Отменить` в тосте, 7 с): для сохранённой продажи / списания — физическое удаление записи (`removeSale`) с пересчётом: если машина стала неполной, `closed:false`, иначе `sum` обновляется. Для пакета расходов — удаление всех записей пакета и пересчёт `sum`. Для частичной оплаты в «Долгах» — откат `paidAmt/paid/paidAt` к прежним.
- **Удаление записи**: кнопка «Удалить» (корзина) в каждой строке (не для менеджера):
  - продажа: лист «Удалить эту продажу?», текст «<что>, <сумма>», кнопки «Удалить продажу» / «Отмена»;
  - списание и расход: лист «Удалить эту запись?», текст «Испорчено: …» или «Расход: <название>, <сумма>», кнопки «Удалить» / «Отмена».
  После удаления машина, у которой появились свободные ящики, переоткрывается (`closed:false`).
- **Удаление машины**: см. 3.2 (только без записей).

Строка продажи в списке: слева «что»: `12 ящиков, 80,5 кг` / `2 паллеты (120 ящиков), …` / `Вся машина (312 ящиков), …` (вес добавляется, если есть); подпись: `14:35, 45 ₸ за 1 кг` (+ `, по формуле X (+Y)` если итог отличается от формулы >=0,005); справа сумма. Ниже, если долг: янтарная плашка «Долг: <имя>» (или «Долг»), плюс «, осталось X» при частичной оплате; кнопки «✓ Отметить оплату» и «Удалить».
Строка списания: янтарная «Испорчено: 3 ящика, 20 кг» + время + «Удалить». Строка расхода: красным «Расход: Комиссия», время, справа `−X`, «Удалить».

### 3.7. Списание испорченного (кнопка «Испорчено»)
- Метка количества «Сколько ящиков испортилось?» (минимум 0). Подсказка «Только вес. Ящики остаются в машине.» при 0 ящиков.
- «Вес с ящиками, кг» необязателен («Вес можно не писать.»).
- Кнопка «Списать» отключена, если нет ни ящиков, ни веса; если ящиков больше остатка; если вес меньше тары ящиков (net < 0); в охлаждении.
- Запись: `unit:'bad'`, `qty=boxes=число`, `kg`, `tare`, `net = kg>0 ? kg − boxes x tare/1000 : 0`, `price:0, total:0, paid:true`.
- Ящики из списания считаются в `used` (уменьшают остаток и могут закрыть машину), деньги не затрагивает.
- Тост «Списано: 3 ящика, 20 кг» (или «… Машина закрыта.») с «Отменить».

### 3.8. Расходы по машине (лист)
Кнопка «Расходы по машине» (на форме продажи и на закрытой машине). Лист: заголовок «Расходы по машине», имя машины, строки «название слева — сумма справа» для: Кара, Комиссия, Плёнка, Заезд, Парковка, Простой + ранее вводившиеся названия расходов (по всем загруженным машинам, до 14 всего), и последняя строка «Другой расход» (текст до 40) + сумма. Строка «Всего расходов» с итогом в валюте машины обновляется при вводе. Кнопки «Сохранить расходы», «Отмена».
Проверки: ни одной суммы -> «Напишите хотя бы одну сумму.»; сумма в «Другой расход» без названия -> «Напишите название расхода.»
Результат: по одной записи `unit:'cost'` на каждую заполненную строку; для закрытой машины пересчитывается `sum`. Тост «Расход: Комиссия, 5 000 ₸» либо «Расходы: 3 записи, 12 000 ₸» с «Отменить» (удаляет все записи пакета). Расходы НЕ влияют на остаток ящиков.
(Смысл слова «Кара» неясен — см. раздел 8.)

### 3.9. Панель владельца / менеджера (`panelView`)
Менеджер видит её как главный экран (шапка «Панель менеджера»); владелец — по кнопке «Панель: что у продавцов» (кнопка «Машины» назад). Если нет продавцов: «Сначала добавьте команду: базары, менеджеров и продавцов.» (менеджеру: «У вас пока нет продавцов. Их добавляет хозяин.»).
1. Переключатель периода: «Сегодня» / «Вчера» / «7 дней» (7 дней = сегодня и 6 предыдущих суток, по локальному времени).
2. Если есть обе валюты — переключатель «Казахстан, ₸» / «Россия, ₽»: валюты не складываются, панель показывает одну страну за раз.
3. KPI-плитки периода: «После расходов» (главная), «Продажи», «Расходы» (`−X`), «Вес без ящиков», «Средняя цена» (`продажи / кг`), «Долги клиентов» (долг по всем машинам области, за всё время, не только за период), «Осталось в машинах» (ящики на открытых машинах), «Испорчено» (если есть), «Разница с формулой» (если !=0). Если для открытых машин ещё не пришли записи: «Загружаю остальные долги…»
4. Раздел «Продавцы»: карточки по продавцам (владелец — сгруппированы по менеджерам, заголовок группы с «после расходов»; последняя группа «Без менеджера»; менеджер видит просто свой список). Карточка: имя + базар; статус последней записи («Запись в 14:35» зелёная точка; «Сегодня пусто, было 7 окт.» янтарная; «Записей нет»); ячейки Продажи / Расходы / После расходов / Вес без ящиков / Средняя цена / Долг; по каждой открытой машине продавца: название, «Осталось N ящиков из M» (+ товар, если не помидоры) и полоса остатка (нажатие открывает машину, «назад» вернёт в панель). Если открытых нет: «Открытых машин нет». Машины без продавца (только для владельца) выводятся отдельной карточкой «Без продавца».
5. Раздел «Машины в продаже» (открытые, старые сверху — «они могут испортиться»): карточка машины с «N-й день», рисунком, остатком и строкой «Продажи X, расходы Y, средняя цена Z».
6. Раздел «Должники»: топ-12 (группировка по имени+продавцу), «<продавец>, с 7 окт.», сумма; при более 12: «И ещё: N». Пусто: «Долгов нет».

### 3.10. «Долги клиентов» (`debtsView`)
Открывается плиткой на главной (не видна менеджеру). Заголовок «Долги клиентов»; «Всего должны» + крупная сумма по каждой валюте. Группы по клиенту (имя без учёта регистра + валюта; без имени -> «Без имени», такие в конце; группы сортируются: валюта, с именем вперёд, по сумме убыв.). Карточка клиента: имя, сумма долга, кнопка «Принять оплату» (кроме только-просмотр), список неоплаченных записей (старые сверху): «<что продали>», «<Машина>, <время> [, из <total>]», справа остаток долга по записи.
Пусто: «Долгов нет» / «Никто не должен. Когда продадите в долг, клиент появится здесь.» (пока записи грузятся: «Загружаю остальные долги…»).
**Принять оплату** (лист «Оплата: <имя>»): текст «Должен: X»; поле «Сколько заплатил?» (предзаполнено полным долгом, выделено); подсказка в реальном времени: «Напишите сумму.» / «Долг будет закрыт полностью.» / «Останется долг: X» / «Это больше долга. Запишу X.» (сумма автоматически ограничивается долгом); кнопки «Сохранить оплату» (при нулевой сумме красная рамка), «Отмена». Оплата распределяется на самые старые записи первыми (FIFO по `at`), частично или полностью; тост «Оплата 5 000 ₸, Рустам» с «Отменить» (откатывает `paidAmt/paid/paidAt`).

### 3.11. Команда (`teamView`, только владелец)
Экран «Команда» с подсказкой «Напишите базары, менеджеров и продавцов. Потом каждый на своём телефоне один раз выбирает своё имя.» Если команда пуста — кнопка «Заполнить по образцу: 4 базара, 2 менеджера, 7 продавцов» (Базар 1–4, Менеджер 1–2, Продавец 1–7; продавцы 1–4 -> базары 1–4 и менеджер 1; продавцы 5–7 -> базары 1–3 и менеджер 2).
Блоки «Базары» (название «Название базара» + выбор страны «Казахстан, ₸» / «Россия, ₽»), «Менеджеры» (имя), «Продавцы» (имя + «Базар не выбран» + «Менеджер не выбран»); у каждой строки корзина («Убрать»); кнопки «Добавить базар / менеджера / продавца». Если имя уже привязано к чьему-то аккаунту — «Вход привязан.» + кнопка «Отвязать».
«Сохранить команду»: пустое имя -> «У каждой строки должно быть имя. Пустые строки уберите.»; ссылки на удалённые базары/менеджеров у продавцов обнуляются; перезапись `config/team` целиком; тост «Команда сохранена».

### 3.12. Пример панели менеджера (демо)
Кнопка «Пример панели менеджера»: подставляет выдуманные данные (по 1–2 машины на продавца, продажи за несколько дней, расходы, списания, долги), реальные данные откладываются; сверху оранжевая плашка «Это пример. Все цифры выдуманные, ничего не сохраняется.» с кнопками смены роли (менеджеры, «Хозяин», продавец) и «Выйти из примера». Любая попытка записи в демо -> тост «Это пример. Здесь ничего не сохраняется.» Для платформы — не нужен (при желании можно оформить как seed-данные).

## 4. Расчёты (точные формулы)

Округления: `round2(n) = Math.round(n*100)/100`; `round3(n) = Math.round(n*1000)/1000`. Вещественная арифметика JS (в Django использовать `Decimal` с теми же квантованиями; см. вопросы).

| Величина | Формула |
|---|---|
| Ящиков для продажи | box: `q`; pallet: `q x max(1, perPallet)`; truck: `left` |
| Остаток `left` | `max(0, truck.boxes − used)`; `used = sold + bad` (суммы `boxes` по записям `unit` не `cost`) |
| Перепродано | если `truck.boxes − used < 0`: `−(boxes − used)` показывается как «N … продано больше, чем было в машине» |
| Макс. паллет | `floor(left / max(1, perPallet))`; ящиков — `left` |
| Чистый вес продажи `net` | `kg > 0 ? round3(kg − n x tare / 1000) : 0`, где `n` — число ящиков в этой продаже, `tare` — граммы на ящик (по умолчанию 450) |
| «Вес неверный» | продажа: `kg>0 и net <= 0`; списание: `kg>0 и net < 0` |
| Сумма по формуле `calc` | `round2(net x price)`; в форме считается, только если `boxes>0 и boxes<=left и вес верный и net>0 и price>0` |
| Итог `total` | `calc`, либо введённая вручную (`round2(typed)`, если `typed>0`) |
| Разница с формулой `diff` (на запись) | `total − calc` (только при `calc>0`); отображается, если `abs >= 0.005` |
| Долг записи `dueOf` | 0 для `bad`/`cost`/`paid=true`; иначе `max(0, round2(total − (paidAmt or 0)))` |
| Получено `gotOf` | 0 для `bad`/`cost`; если `paid` — `total`; иначе `min(total, paidAmt or 0)` |
| Сводка машины `calc(list)` | `sold = Σ boxes (продажи)`, `soldKg = round3(Σ net)`, `bad = Σ boxes (bad)`, `badKg = round3(Σ net bad)`, `used = sold+bad`, `paid = round2(Σ gotOf)`, `due = round2(Σ dueOf)`, `cost = round2(Σ total cost)`, `diff = round2(Σ diff)` |
| «Продажи» (деньги) | `round2(paid + due)` (все продажи независимо от оплаты, до вычета расходов) |
| «После расходов» | `продажи − расходы`, отрицательное отображается с `−` |
| Средняя цена | `продажи / soldKg` (деньги по всем продажам, включая неоплаченные, на чистый вес); 0, если кг = 0 |
| Закрытие машины | сразу после записи, если `used >= truck.boxes` (>=, т. е. и при перепродаже) |
| Распределение оплаты клиента | по возрастанию `at`: `pay = min(due записи, остаток платежа)`; `got = round2(paidAmt + pay)`; `full = got >= total − 0.005`; тогда `paidAmt = full ? total : got`, `paid = full`; платёж ограничен общим долгом клиента |
| Паллет на рисунке | `n = max(1, ceil(boxes/perPallet))`, но не более 44 (тогда `cell = boxes/44`); заливка `i`-й ячейки = `clamp(left − i x cell, 0, cell)/cell x 100%` |
| Номер дня машины | `floor((now − createdAt)/86400000) + 1` |

Форматирование чисел: `Intl.NumberFormat('ru-RU')`; деньги и ящики — максимум 2 знака после запятой, вес — максимум 3; разделитель тысяч — пробел, десятичный — запятая. Деньги: `<число> <символ>`, символ ПОСЛЕ суммы. Валюты: `KZT` -> `₸` («Тенге», Казахстан), `RUB` -> `₽` («Рубли», Россия); по умолчанию тенге. Отрицательное — символом `−` (U+2212), положительная разница — `+`. Суммы в разных валютах никогда не складываются: долги на главной «A ₸ + B ₽», в панели переключатель страны.
Разбор ввода: `parseMoney`/`parseKg` — убирают пробелы, первую запятую заменяют на точку, выбрасывают всё кроме цифр и точки (знак минус вырезается, поэтому отрицательных чисел ввести нельзя); `parseKg` дополнительно округляет до 3 знаков. Ввод форматируется на лету: тысячи пробелом, максимум 12 цифр в целой части, число знаков после запятой зависит от поля (вес — 3, цена и суммы — 2, ящики — 0).
Склонения (`plural`): `ящик/ящика/ящиков`, `паллета/паллеты/паллет`, `ящик остался/ящика осталось/ящиков осталось`, `запись/записи/записей` — правила: 1 (кроме 11) -> one; 2–4 (кроме 12–14) -> few; иначе many; число берётся по модулю и округляется.

## 5. Правила и валидация (сводка)

| Ситуация | Поведение | Сообщение |
|---|---|---|
| Новая машина: ящиков < 1 | сохранение блокируется | «Напишите, сколько ящиков в машине.» |
| Новая машина: на паллете < 1 | блок | «Напишите, сколько ящиков на 1 паллете.» |
| Правка: ящиков меньше уже списанного | блок | «Уже продано или списано: N ящиков. Меньше поставить нельзя.» |
| Товар «Другое» без названия | блок | «Напишите название товара.» |
| Тара пустая | = 450 | — |
| Тара > 20000 | обрезается до 20000 | — |
| Имя машины пустое | «Машина N» | — |
| Продажа: ящиков 0 / больше остатка | кнопка отключена; ввод подрезается | «В машине осталось только N ящиков» / «Больше нельзя: целых паллет осталось N (M ящиков)» / «На целую паллету не хватает. Осталось N ящиков.» |
| Продажа: вес не введён | блок | «Напишите вес с весов.» |
| Продажа: вес меньше или равен весу пустых ящиков | блок (красная рамка + подсказка) | «Вес меньше, чем весят пустые ящики (N ящиков по T г).» |
| Продажа: цена не введена или 0 | блок | «Напишите цену за 1 кг.» |
| Итог введён вручную | допускается любое >0; расхождение показывается и хранится | «По формуле: X. Разница: +Y» |
| Продажа в долг без имени | допускается | в списках «Без имени» |
| Списание: ни ящиков, ни веса / ящиков больше остатка / вес меньше тары | кнопка «Списать» отключена | то же, что для веса |
| Расходы: нет ни одной суммы | блок | «Напишите хотя бы одну сумму.» |
| Расходы: сумма без названия (строка «Другой расход») | блок | «Напишите название расхода.» |
| Оплата: сумма <= 0 | красная рамка | «Напишите сумму.» |
| Оплата больше долга | ограничивается долгом | «Это больше долга. Запишу X.» |
| Команда: пустое имя | блок | «У каждой строки должно быть имя. Пустые строки уберите.» |
| Сохранение не удалось | тост 20 с с «Повторить» | «Не сохранено. Проверьте интернет.» |
| Квота хранилища (`quota_exceeded`) | тост | «Память заполнена. Скажите хозяину.» |
| Имя в команде уже занято | тост | «Это имя уже занято.» |

Прочие правила:
- Отрицательные числа ввести невозможно (все поля чистят нецифровые символы).
- Количество нельзя сделать меньше 1 (0 для «Испорчено»).
- Продажа без веса невозможна (вес обязателен); цена обязательна; в старых данных могла быть продажа без веса (`net` отсутствует) — формат строки «за 1 ящик».
- Удалить машину можно только если по ней нет записей (кнопка не показывается иначе).
- Машина закрывается автоматически, когда `used >= boxes`; открывается автоматически, если ящики освободились (удаление записи, увеличение количества, открытие закрытой машины с остатком).
- Расходы можно добавлять к закрытой машине; продажи и списания — нет (форма скрыта).
- Двойное нажатие «Сохранить»: защита паузой 700 мс.
- Менеджер и демо — только просмотр; ни одна кнопка записи не показывается.

## 6. Мультипользовательность

### 6.1. Кто что видит
- Продавец: только машины, у которых `seller == его id` (в локальном режиме без аккаунта дополнительно — машины, у которых продавец не найден в команде); подписки на продажи ограничены: открытые машины, машины с долгом, закрытые за последние 48 часов (владелец/менеджер — за 8 суток), плюс открытая в данный момент. Максимум 30 открытых и 56 подписок всего.
- Менеджер: машины продавцов с `manager == его id`; панель; ничего не изменяет.
- Владелец: все машины и вся команда.
- Не в команде (с аккаунтом): ничего.

### 6.2. Идентификация (capability `user`)
- `user.id()` -> `uid`. Если аккаунт есть и привязан к имени в команде (по `uid` в `managers`/`sellers`) — роль и имя фиксируются автоматически, поменять нельзя (`bound`); иначе владелец (по `isOwner()`), иначе заблокирован с предложением занять свободное имя.
- Занятие имени = запись `uid` в `config/team`; освободить может только владелец («Отвязать»).
- Без аккаунта (локальный режим) имя выбирает сам пользователь и оно запоминается в `localStorage['tomato-me-v1']` — это не защита, а удобство.
- `user.can('data.write') === false` -> приложение уходит в локальный режим (не видит общие данные).

### 6.3. Синхронизация и конфликты
- Живые подписки (onSnapshot) на `trucks`, `config/team` и `trucks/{id}/sales` для нужных машин; любое изменение с другого телефона приходит автоматически, экран перерисовывается через `requestAnimationFrame` (не чаще раза за кадр).
- Записи на один и тот же документ выстраиваются в очередь (`inTurn` по ключу `trucks/{id}`, `{id}/{saleId}`, `config/team`).
- Сетевая ошибка при записи: одна повторная попытка через 400–1000 мс; если не вышло — тост «Не сохранено. Проверьте интернет.» с «Повторить» (20 с).
- Транзакций нет: «последняя запись побеждает». Два продавца одной машины, продающие одновременно, могут продать больше остатка (отсюда состояние «перепродано»); закрытие машины делается отдельной записью клиентом, который первым увидел `used >= boxes`. `config/team` перезаписывается целиком. Привязка uid проверяет занятость по локальной копии команды (гонка возможна).
- Сканирование QR на машине, которая уже есть, перезаписывает её параметры значениями из QR (может откатить более новую правку, пока QR не обновлён).
- Статистика закрытых машин берётся из `sum` без загрузки их записей.

### 6.4. Выгрузка файлов (capability `downloads`)
Единственная «выгрузка» — PNG картинки QR-кода, имя файла `QR <название машины>.png` (ширина ~ 880 px + подвал 180 px; подвал: название и «Товар, N ящиков[, X за 1 кг]»). Экспорта отчётов, CSV и колонок НЕТ. Если платформе нужен Excel/CSV по продажам, его надо проектировать отдельно (кандидаты колонок: дата-время, машина, продавец, базар, товар, тип (ящик/паллета/вся машина/испорчено/расход), ящиков, вес с ящиками, тара, чистый вес, цена/кг, по формуле, итого, оплачено, долг, покупатель).

## 7. UX-детали, которые стоит повторить

- Mobile-first (телефон/iPad продавца на базаре): все цели нажатия >= 44–48 px, основные кнопки 56–76 px, шрифты крупные (число в степпере 52 px, вес/цена 34 px). Максимальная ширина контейнера 1200 px; список машин 1/2/3 колонки на 0/760/1100 px; форма продажи на ширине >=520 px: единицы в ряд (4), вес и цена рядом.
- Листы (диалоги) прижаты к ВЕРХУ экрана на телефоне (клавиатура не закрывает), на >=700 px по центру; закрываются Esc и кликом по подложке; `role="dialog" aria-modal`.
- Степпер `− N +`: по умолчанию 1; при фокусе число выделяется целиком; поля с `inputmode=numeric/decimal`, `autocomplete=off`.
- Числа вводятся с пробелами по тысячам «на лету» (курсор не прыгает), запятая и точка — десятичный разделитель.
- Сумма предзаполняется сама, а ручная правка помечается «По формуле: … Разница: …».
- Цена запоминается от последней продажи — продавец вводит только количество и вес.
- Тосты с «Отменить» на 7 секунд после сохранения продажи, списания, расходов, оплаты (быстрая отмена вместо диалогов подтверждения); подтверждения только для удаления.
- Визуальный остаток: рисунок кузова с паллетами, закрашиваемыми по мере продажи; цвет товара (красный для помидоров, зелёный для остального); янтарный для долгов/предупреждений; красный для расходов/ошибок. Тема светлая/тёмная по `prefers-color-scheme`.
- Русские склонения числительных везде (ящик/ящика/ящиков, паллета/паллеты/паллет, осталось/остался).
- Подсказки на живом языке, без технических терминов («Напишите вес с весов.», «Сфотографируйте ближе и ровнее.»).
- Доступность: `aria-pressed` на переключателях, `aria-label` у иконок-кнопок, `aria-live`-подобный `role=status` у тостов, видимый фокус, `prefers-reduced-motion`.
- Адаптация к iPad (контейнерные запросы), `viewport-fit=cover` и safe-area отступы.
- Весь текст интерфейса — в одном словаре `T` (удобно для i18n); приложение однозначно русскоязычное.
- Шрифты: Sofia Sans / Sofia Sans Condensed (Google Fonts), цифры табличные.
- Внешние библиотеки: qrcode-generator@1.4.4 и jsQR@1.4.0 (jsdelivr); без интернета QR не работает (в React: пакеты `qrcode`/`jsqr` или `BarcodeDetector`, а в платформе, скорее всего, лучше живой `getUserMedia`-сканер).

## 8. Открытые вопросы / неоднозначности

1. Что означает расход «Кара»? (в источнике не расшифровано). Нужен перечень расходов от заказчика; в приложении 6 предустановленных названий + свободные.
2. Валюта и страны: только KZT и RUB, а по домену YGT есть и другие рынки? Должна ли валюта быть на машине, на продавце или на базаре (в источнике приоритет: машина -> базар продавца -> KZT)?
3. Связь с существующей моделью платформы: считать ли «машину» из этого приложения существующим `Shipment` (отгрузка YGT), или это отдельная сущность «партия на базаре»? Где в платформе хранить продавцов/базары (Users + новая Org-структура)?
4. Сведение с платформенным учётом: ящики -> вес продукции, что делать с «Испорчено» (списание в квоту/склад)? Нужна ли интеграция с вес-мастером (Weightmaster)?
5. Тара: учитывается только вес пустого ящика; вес паллеты (поддона) не вычитается. Нужен ли отдельный параметр? Для «Вся машина» вес всего кузова минус `остаток x тара` — реально ли весят всю машину с ящиками?
6. Нет возможности «снять оплату» (отменить «Отметить оплату») и нет тоста отмены для неё; в платформе, вероятно, нужна.
7. Нет редактирования уже сохранённой продажи (только удалить и ввести заново); нужен ли редактор?
8. Удаление машины без записей в общем режиме удаляет только документ; удаление записей при удалении «пустой» машины не затрагивается. При наличии записей машину удалить нельзя вообще — как архивировать/мягко удалять?
9. Закрытие машины хранит `closedAt` и `sum` без обнуления при переоткрытии; `sum` на открытых машинах может быть устаревшим. На сервере это лучше считать агрегатом (annotate) — подтвердить.
10. Конкурентность: два продавца на одной машине могут продать больше остатка. Нужна ли серверная проверка остатка с блокировкой (рекомендуется) или оставить допустимой «перепродажу»?
11. Границы дня «Сегодня/Вчера/7 дней» считаются по часовому поясу устройства; на сервере нужен фиксированный часовой пояс (KZ/RU — несколько).
12. Привязка аккаунта к имени продавца/менеджера (`uid` внутри `config/team`) — в платформе это естественно заменить на `User` + роли/привязку к продавцу; нужны ли «Хозяин»/менеджер как роли существующей RBAC-матрицы (см. заметки платформы про Adding a Role).
13. Экспорт: нужен ли Excel/CSV отчёт по продажам/долгам (в источнике его нет, хотя ожидается в ТЗ).
14. QR: кодирует параметры машины, а не ссылку. В платформе, вероятно, стоит кодировать URL/идентификатор машины (не копию параметров), иначе скан со старой наклейки откатывает правки. Нужен ли живой сканер камерой вместо «сфотографировать и выбрать файл»?
15. Список открытых машин подписывается максимум на 30 штук без сортировки; на серверной пагинации это не нужно.
16. Предполагалось «цена за ящик» в старых данных (`forOne` — «X за 1 ящик»): мигрировать ли старые продажи? В новых данных всегда есть вес.
17. Лимиты (20000 г тары, 999999 ящиков, 12 цифр, 40/60/24 символов) — взять как есть или пересмотреть для платформы.
18. Склонения «ящик остался» при дробных числах не предусмотрены (все количества целые, кроме веса).

| QR | кодировать UUID/URL машины; сканер на `getUserMedia` + jsQR/BarcodeDetector; PNG генерировать на клиенте или сервере |
